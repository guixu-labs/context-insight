# 从 session 到 memory

输入完整迁移转录，输出问题清单、通过机械检查的情景卡和 `memory/index.md`。你是编排者，负责拆分、派工、收集和归并；每个问题由独立子代理调查。

这是薄编排入口，没有另一套解析器、卡片模板或校验脚本。使用同一技能包内的三个相邻 skill；普通文件读取即可打开，不要求宿主预先注册技能名称：

- [migloop-repair-triage](../migloop-repair-triage/SKILL.md)：你先完整读取，用于拆分和生成 job。
- [migloop-build-cards](../migloop-build-cards/SKILL.md)：派工前完整读取，调查员也读取，用于归因、制卡和处理反馈。
- [migloop-memory-maintain](../migloop-memory-maintain/SKILL.md)：收卡后完整读取，用于提炼并发布经验。

三个处理 skill 随发布包一起安装；它们各自携带所需脚本，Python 3.12+ 即可运行。先确认这三个路径与 Python 可用，缺包时报告缺失路径，不重写脚本替代。第四个 recall skill 留给下一次迁移，本轮不安装 hook、不启动新迁移。

## 1. 定范围，拆任务

只给根转录时，同时查同 session 的子转录；生成与修复分属多个会话时，将两段及其后代纳入同一材料池。缺少生成材料就如实记录，修复者的总结不能补成生成期原文。

有指定输出目录就使用它；否则在材料目录之外新建 `migloop-memory-<会话短名>-<时间>/`。默认建独立新库，只有用户指定已有库时才更新；不自动读入旁边的旧实验、卡片或经验。历史工程和材料只读，产物放工作目录。

按 triage skill 确定生成结束与观察截止，输出 `repair-tasks.yaml`。范围覆盖截止内实际保留的应用修改，包括主会话直改与脚本修改，不只看带 round 编号的工单。生成过程中的收敛步骤作为追溯背景，是否纳入本轮修复取决于已声明边界。

使用 triage 的 metadata + dispatch 命令生成 `metadata.json` 和 `dispatch/`，provenance 的材料必须同时包含生成与修复。已冻结的材料与匹配元数据可以复用；需要合池时保留文件内容及各自相对目录，只复制相关转录，不带入宿主自己的 memory。无实际修复时交付清单及说明，不凭空制卡。

## 2. 共用索引，独立制卡

有 job 后，主代理用 build-cards 的 `cases.py prepare --job FIRST_JOB` 准备一次索引，再派工。调查员使用同一 dispatch 下的 job，query/pack 自动复用索引与各任务反馈，不各自重建数据库。

每个问题派一个独立上下文子代理，同时最多 6 个制卡子代理并行（不含编排主代理）；宿主可用并发不足时下调，完成一个补派一个。只提供以下交接信息，不附主代理猜测的根因或其他任务的结论：

> 请读取 `<build-cards/SKILL.md 的绝对路径>`，完成 `<job.json 的绝对路径>`。完整转录入口为 `<材料池>`，本任务产物写到 `<cards/job目录>`。按 skill 调查、核验并交付最终卡路径与未决范围。可用 Python 为 `<已确认的解释器>`。

调查方式、模板及反馈处理都遵循 build-cards。首稿到最后一稿保存在任务目录，检查不通过的部分交回原调查员继续处理；只有 pack 返回 `status: valid` 的正式卡进入汇总。环境问题或材料缺口如实留档，继续其他任务，不通过修改检查器、回执或虚构关系消除失败。

主代理收集每个 job 的最终卡路径、未决目标或阻塞原因，无需重读所有调查过程，也不另派语义审核。某些目标未决但卡片合法时，按卡片已支持的范围交给归并；同一 job 的多稿只选最终通过的一稿。宿主不能派独立子代理时，报告当前限制和已完成清单，不把同上下文串行调查声称为独立派工。

## 3. 从正式卡归并并交付

收集结束后，按 maintain skill 对新库 init（已初始化则 snapshot），导入最终卡，自主提炼、合并或分支，保存提案并 apply，最后 export 到新的 `memory/` 阅读目录。归并由你完成，脚本核格式、来源和版本；不预设卡片或 lesson 数量，不要求一卡一经验。

只有部分任务完成时，也可发布这部分卡片支持的经验，并标明未完成范围。没有有效卡就交付清单、稿件和反馈，不把空库称为经验成果。

最终给出：问题清单、逐任务最终卡或缺口、新库 revision、`memory/index.md` 完整路径和简短 `REPORT.md`。报告记录实际用时及可取得的 token，不额外制作大篇审计表。保持 `材料 → job → 最终卡 → lesson 来源绑定` 可追溯；本轮到本地交付为止，不自动推送远端或修改被调查工程。
